## 3. 采集建议（要采哪些真实录屏、怎么采）

### 3.1 采集原则（先于工具）

1. **真实**：只录本机真实运行的 `web/` SPA（`npm run dev` 后浏览器访问），不摆拍、不补画未发生的界面。

### 3.3 采集方法（Windows 本机）

- 启动：`cd web && npm run dev`，用真实 Chrome 窗口（非无头）打开本地 dev server 地址。
- 录制工具：OBS Studio 或 Windows 自带录屏；参数建议 **1920×1080、30 fps、SDR、8-bit、无缩放、固定窗口尺寸**、关闭系统通知与鼠标高亮以外的美化。
- 每段**单文件**保存，命名 `录屏/R1-home.mp4` … `录屏/R8-stats.mp4`（放到 `参赛材料/视频/录屏/`，仅本目录内新建）。
- 一段只录一个业务事件；操作之间留 0.5–1 s 静止，便于后续按「移动/落定/读懂」分拍。
- 录完用 `ffprobe` 记录真实时长/帧率/分辨率，登记进 `上屏文字出处表.md`（录屏即为上屏画面的出处）。
- **HDR 检查**：若素材被 `om check`/`om render` 拒绝，先用完整版 ffmpeg 转 SDR 再入片。

### 3.4 口播 / 音频采集

- 主方案为**无旁白**（`treatment.md`、`口播稿.md`）。若要中文口播：本人朗读 `口播稿.md` 的字幕文本，录成单声道 wav/m4a，按分镜号命名，用 `om voice <dir> --audio <file> --fit` 生成词轴与 `.srt`；**不要**用 Windows 不可用的 `say:Tingting` 或无声调的 espeak 中文。
- BGM：优先用技能自带 `references/scores/*.abc` 经 `om sound` 生成，或 `OM.music({...})`；确认无版权问题后再用。
