## 1. 命令序列

### 1.1 任务清单顺序（环节清单）

`doctor → fork → check → qa → still --at 四帧 → render → 审片`

### 1.2 实际可执行顺序（按真实依赖修正，逐条给理由）

> 说明：`om qa` 检查的是**渲染产物**（`om.js:276-280`：传目录时取 `out/` 下最新视频，若无则报 `nothing rendered yet — run om render first`），故终版 `qa` 必须在至少一次 `render` 之后；`om still` 可对任意页面/项目出帧（`om.js:39,297-299`），不依赖 render，可在 check 之后先出关键帧人工核看。下表按依赖给出可一键执行的顺序，同时**覆盖上面全部环节**。

#### 步骤 0 — 环境前置（关键）
```bash
export PATH="/c/Tools/ffmpeg/bin:$PATH"
export OM="node D:/Study/AI_Space/dsh/huashu-motion/cli/om.js"
export FILM="参赛材料/视频/film"
```

#### 步骤 1 — `doctor`（必须 0 errors / EXIT=0）
```bash
$OM doctor
```
期望四行全绿；若出现 `✗ encoders missing …`，说明 PATH 未前置，回到步骤 0。

#### 步骤 2 — 建片 / 改画幅（`new` 与 `fork`）
```bash
# 首次建片（二选一）：模板或空白项目
$OM templates                                   # 先看有哪些模板
$OM new "$FILM" --template <id>                 # 或直接 $OM new "$FILM"

# 若从竖版/其他画幅模板改成 16:9，用 fork 重定画幅：
$OM fork "$FILM" "${FILM}-1080" --size 1920x1080
```
- `--size 1920x1080`：`om.js:36`、`fork.js:27-35` 会写入 `data-width/data-height`。
- 分辨率也可直接在根元素写 `data-width="1920" data-height="1080"`（`capture.js:17` 默认 1920×1080；`check.js:30` 要求根元素带 `data-composition-id/data-width/data-height`）。

#### 步骤 3 — 写 `index.html`（单一 composition，引用真实素材）
- 全项目根目录**只能有一个** composition `*.html`，草稿放 `tools/` 子目录，否则 `check` 报「several root compositions」（`SKILL.md:40`）。
- 根元素：`data-composition-id` + `data-width="1920"` + `data-height="1080"` + 可选 `data-fps="30"`（`render.js:31-33`）。
- 画面只引用真实文件：`web/screenshots/*.png`、`web/index.html:5` 内联钢印 SVG（真实色值 `#ede8db/#12100e/#ca6c52`）、`web/public/data/chefs.json`（仅数值出处）。
- 上屏文字只用 `上屏文字出处表.md` 中判定「可上屏」的条目；无来源的一律不上屏。
- 动画只改 `transform`（`x/y/scale/rotation`），**不改 `left/top/width`**（`SKILL.md:40` check 拒绝 layout motion）。
- 包装层初态明确设置、`fromTo` 用 `immediateRender:false`，避免 history-dependent（`product-demo-continuity.md:52`、`SKILL.md:40`）。
- 时长由 **GSAP 时间轴**决定；`om` **没有 `--duration`**（`om --help` 全表无此参数，`render.js` 按帧数导出）。方案 A 时间轴 = `分镜节奏单.md` 的 86 s。

#### 步骤 4 — 本地化中文字体
```bash
$OM fonts add "Noto Sans SC" "$FILM"
```
- 已 bundled（`om fonts` 实测），无需联网；不依赖 `web/index.html:10-12` 的在线 Google Fonts。

#### 步骤 5 — `check`（必须 0 errors）
```bash
$OM check "$FILM" --samples 24
# 或机器可读：$OM check "$FILM" --json
```
- `--samples 24` 是默认值（`om.js:267`）；有 `error` 时进程 `exitCode=1`（`om.js:268`），**必须先修到 0 errors 再渲染**。
- 检查项：结构/脚本/文件/运动规则 + 采样帧裁切/遮挡/低对比文字/空白结尾/history-dependent（`SKILL.md:40`）。
- 若文字被全屏装饰层（纸纹/颗粒）盖住，把该层放到内容层**之前**；有意的重叠加 `data-layout-allow-occlusion`（`SKILL.md:40`）。

#### 步骤 6 — `still --at` 四帧人工核看（hook / hero / densest / end）
```bash
# 一次出四个时刻（om.js:39 支持 --at 0,2.5 逗号列表）
$OM still "$FILM" --at 3.0,19.0,68.0,80.0

# 或分四次显式命名（--out，om.js:39,299）
$OM still "$FILM" --at 3.0  --out "$FILM/stills/01-hook.png"
$OM still "$FILM" --at 19.0 --out "$FILM/stills/02-hero.png"
$OM still "$FILM" --at 68.0 --out "$FILM/stills/03-densest.png"
$OM still "$FILM" --at 80.0 --out "$FILM/stills/04-end.png"
```
- 四帧对应 `分镜节奏单.md`：C01 Hook(3.0) / C03 全貌 Hero(19.0) / C10 数据最密(68.0) / C11 收束(80.0)。
- 人工核看：裁切文字、碰撞、空白帧、字号（`SKILL.md:48`）；**看每个场景切换后的第一秒**（闪现元素只在这里出现）。
- 只检查截图不能声称审过运动（`verification.md:11`）。

#### 步骤 7 — 声音（有 BGM 时；无旁白方案见 `口播稿.md`）
```bash
$OM sound "$FILM"            # 由 om-score / OM.music / OM.sfx 生成音轨，并打印能量曲线
```
- 若有意静音且无 BGM，渲染加 `--silent`（`om.js:258` 会告警 `no soundtrack`）。

#### 步骤 8 — `render`（先无 blur 迭代，终版加 blur）
```bash
# 迭代版：快，便于反复调时间轴
$OM render "$FILM" --fps 30 --format mp4 --workers 8 --silent

# 终版：加运动模糊，显式命名输出
$OM render "$FILM" --fps 30 --format mp4 --workers 8 --blur 8 \
  --out "$FILM/out/star-chef-final.mp4"
```
- 默认输出 `<dir>/out/<name>-vN.mp4`，**永不覆盖**（`SKILL.md:26`、`om.js:29`）；`--out` 可显式指定（`om.js:260` 实测支持 `out: flags.out && resolve(flags.out)`）。
- 编码：mp4 = H.264 `libx264` + `-movflags +faststart`（本轮 `ffmpeg -h muxer=mp4` 确认支持 faststart；doctor 确认 encoders mp4 ✓）。
- `om render` 会**先刷新音轨**（`om.js:256-258`）；改过时间轴后要重跑 `om sound`（`SKILL.md:50`）。

#### 步骤 9 — `qa`（对渲染产物）
```bash
$OM qa "$FILM"                              # 取 out/ 下最新视频（om.js:276-280）
$OM qa "$FILM/out/star-chef-final.mp4"      # 或直接给文件
$OM qa "$FILM/out/star-chef-final.mp4" --loop   # 循环片才加 --loop
```
- 检查单帧 pops / dead time / hard cuts / motion curve / loop seam（`om.js:30`、`SKILL.md:30,48`）。

#### 步骤 10 — 技术取数 + 绑定 SHA + 独立审片
```bash
ffprobe -v error \
  -show_entries format=duration,size:stream=codec_name,width,height,r_frame_rate \
  -of default=noprint_wrappers=1 "$FILM/out/star-chef-final.mp4"

sha256sum "$FILM/out/star-chef-final.mp4" | tee "$FILM/out/SHA256.txt"
```
- 审片报告模板见第 4 节；**报告必须绑定该 SHA**（`verification.md:5`）。

#### 可选 — `om studio`
`om studio "$FILM" --no-open` 是 127.0.0.1 本地服务（`SKILL.md:38`），沙箱可能阻断；被阻时在沙箱外运行或跳过，但**不能因此跳过 `check`/`still`/`qa` 的视觉检查**。

## 2. 全部参数取值与理由（附真实源码行号）

| 参数 / 设定 | 取值 | 理由与依据 |
|---|---|---|
| PATH 前置 `/c/Tools/ffmpeg/bin` | 必须 | 默认 PATH 命中 2013 残缺 ffmpeg，`om doctor` EXIT=2；前置后 EXIT=0（本轮实测） |
| 调用方式 | `node .../cli/om.js` | `dsh/.../bin/om` 不存在；启动器在 `skills-cage/.../bin/om` |
| `--fps` | **30** | `render.js:31-33` 默认 30（取 `data-fps`，否则 30）；`render.js:36` 合法值仅 `24/25/30/50/60`，其他报错 `fps must be 24, 25, 30, 50 or 60` |
| `--format` | **mp4** | 交付格式；H.264 `libx264` + `-movflags +faststart`。可选 `mov\|webm\|gif`（`om.js:29`），分别依赖 `prores_ks` / `libvpx-vp9+libopus` |
| `--blur` | **8**（终版） | `render.js:40`：`Math.min(8, Math.floor(240/fps))`，30 fps → 8；`render.js:42` 校验 `fps*blur<=240`（30×8=240 恰通过）；**60 fps 时 `--blur 8` 会 480>240 被拒**，须降到 4 |
| `--workers` | **8** | `om.js:32` 默认最多 8 个浏览器并发 |
| `--silent` | 无音轨时加 | `om.js:258` 无音轨会告警；`--silent` 明确「有意静音」。有 BGM 时**不要**加 |
| `--out` | 终版显式路径 | `om.js:260` 实测 `out: flags.out && resolve(flags.out)`；默认 `<dir>/out/<name>-vN.mp4` 永不覆盖（`SKILL.md:26`） |
| `--samples` | **24** | `om.js:267` 默认采样帧数；check 用它做裁切/遮挡/低对比/空白结尾检查 |
| `--at` | **3.0,19.0,68.0,80.0** | `om.js:39,299` 支持逗号列表；对应 hook/hero/densest/end 四帧 |
| `data-width/height` | **1920×1080** | `capture.js:17` 默认 1920×1080；`check.js:30` 根元素必需；`fork.js:27-35` 写入 |
| `data-fps` | 30（可选） | `render.js:31-33`；与 `--fps` 一致 |
| `data-composition-id` | 必需 | `check.js:30` 无则报 error |
| 时长 | **无 `--duration`** | `om --help` 全表无此参数；由 GSAP 时间轴决定，方案 A = 86 s（`分镜节奏单.md`） |
| 字体 | `Noto Sans SC` | `om fonts` 已 bundled；不依赖在线 Google Fonts |
| `om studio` | 可选 | `SKILL.md:38` 127.0.0.1 本地服务，沙箱可能阻断 |

## 5. 本轮未产出成片 / 未做 demo 的原因（如实说明）

**本轮不产出最终 3–5 分钟 MP4 成片**（任务明确要求），且**未制作 `参赛材料/视频/demo/` 的可选短片**。原因具体、可核查：

1. **缺真实操作录屏（决定性）**：仓库零 mp4/mov/webm/gif，26 张均为静态截图。`craft.md:9`「缺失就标记缺口，不用假界面补出未发生的操作」、`product-demo-continuity.md:30`「不要剪成点击即完成」——没有 R1–R8 录屏，任何「操作→结果」镜头都不能做；只做静态轮播又难以满足「读懂/状态变化」分拍，且不构成「演示视频」。
2. **截图多为开发中间态**：26 张中约 8 张是 `before/after`、`data-fix-*`、`lineage-empty`、`year-label-fix` 等调试/修复态，还有多张超长整页（1904×8916）与超宽拼接（3864×1142）。把它们当「产品定稿界面」上屏有误导风险；本轮未对 26 张逐一做视觉核看，不臆断画面内容。
3. **中文口播与用户确认缺失**：Windows 无可用中文 TTS（`say:Tingting` 为 macOS 专属、espeak 中文无声调），无自备录音；用户对内容、时长、旁白方案、版权行是否上屏均未确认。未经确认先出片容易被否（`verification.md:13` 被否样片须降为技术回归案例）。
4. **渲染耗时与明确指令**：15–30 s @ 30 fps 需数百帧 Chrome 逐帧截图，叠加 26 张 3–4 MB 大 PNG，预计耗时较长；任务明确「不要卡在渲染上」「把精力放在 6 份文档上」。
5. **依赖其实基本就绪，但不足以「安全产出」**：本轮已实测 `om doctor` 前置完整版 ffmpeg 后全绿、`Noto Sans SC` 已 bundled、CLI/references/scores 齐全——**渲染链路可用已得到确定性验证**，但「能跑通」不等于「内容真实且经确认」。故不以一条可能被否的样片替代文档交付。

> 因此本轮把「可确定性交付」落在：6 份文档 + 实测 doctor 结论 + 可一键执行的命令序列 + 8 条验收 + 审片模板。补齐第 5 节前置后，按第 1 节命令即可确定性产出成片；**demo 片若将来制作，必须 `om check` 0 errors、附上屏文字出处表，并明确「不是 3–5 分钟成片、不是提交件、不替代验收」**。
